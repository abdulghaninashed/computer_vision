# نظام مراقبة وتحليل حركة المرور

مشروع رؤية حاسوبية لتحليل فيديو حركة المرور، وتتبع المركبات وعدّها عند عبورها خطًا محددًا. يعرض التطبيق الفيديو والإحصائيات في واجهة ويب محلية، ويوفر تقريرًا بعدد المركبات المسعّرة وإيراداتها.

## 1. المتطلبات

- Python و`pip`.
- ملفات المشروع.
- أوزان النموذج `models/best(7).pt`. هذا الملف غير مضمّن في مستودع Git لأن مجلد `models/` مستثنى في `.gitignore`. ضع ملف الأوزان في هذا المسار قبل التشغيل.

## 2. التنصيب والتشغيل

من مجلد المشروع الرئيسي، أنشئ بيئة افتراضية:

```bash
python -m venv .venv
```

فعّل البيئة:

```bash
# Linux أو macOS
source .venv/bin/activate

# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

ثبّت المكتبات المطلوبة وشغّل التطبيق:

```bash
python -m pip install -r requirements.txt
python src/main.py
```

يفتح التطبيق على `http://127.0.0.1:5000`. اختر فيديو بصيغة MP4 أو AVI أو MOV أو MKV ثم اضغط **بدء التحليل**. يمكن تعديل خط المنتصف من الإعدادات، وإيقاف التحليل مؤقتًا واستئنافه. يعرض زر **التقرير** جدول المركبات والإيرادات. عند الضغط على **إيقاف** يعرض تقرير الجلسة ثم يصفّر العدّادات بعد انتهاء التتبع.

## 3. كيف يعمل المشروع

1. يحمّل التطبيق نموذج YOLO من `models/best(7).pt` ويعالج إطارات الفيديو باستخدام Ultralytics وOpenCV.
2. يستخدم التتبع المستمر `ByteTrack` للاحتفاظ بمعرّف كل مركبة بين الإطارات.
3. يعتمد العدّ على عبور أسفل صندوق المركبة خطًا أفقيًا عند 75% من ارتفاع الإطار. يُحتسب معرّف التتبع مرة واحدة في الجلسة.
4. يحدد موضع المركبة بالنسبة إلى خط المنتصف اتجاهها: ذهاب أو إياب.
5. تسعير التقرير: السيارة 1$، الفان 1.5$، الشاحنة 2.5$، والباص 2$. إجمالي المركبات يشمل المركبات المكتشفة؛ أما الإيراد فيُحسب للفئات الأربع المسعّرة.

## 4. البيانات والتدريب

بحسب دفتر التدريب الموجود في `train_in_colab/finally_trainning.ipynb`، اعتمد التدريب على مصدرين:

- مجموعة مخصصة من Roboflow، المشروع `abdulghani`، الإصدار 3.
- مجموعة COCO 2017، مع اختيار فئات `motorcycle` و`car` و`truck` ودمجها مع بيانات Roboflow وإعادة مواءمة ترقيم الفئات.

يسجل الدفتر استخدام 6,004 صور تدريب و918 صورة تحقق بعد تجهيز البيانات. جرى ضبط تدريب YOLO11n المسبق التدريب على 25 حقبة، بحجم صور 640 ودفعة 16، مع تجميد أول 10 طبقات وإعداد الإيقاف المبكر `patience=15`.

تتضمن إعدادات Ultralytics المسجلة في الدفتر تكثيرًا للبيانات أثناء التدريب، بما في ذلك Mosaic والقلب الأفقي وتغييرات HSV والمقياس. لا يصف الدفتر هذه التحويلات على أنها إعدادات مخصصة للمشروع؛ بل تظهر ضمن إعدادات التدريب المستخدمة.

## 5. التحديات الفنية وطريقة التعامل معها

- **منع تكرار العدّ:** قد يظهر الجسم نفسه في إطارات كثيرة؛ يستخدم التطبيق معرّفات ByteTrack ومجموعة للمركبات التي عُدّت.
- **تحديد لحظة العبور والاتجاه:** يحتفظ التطبيق بموضع المركبة بين الإطارات ويقارن عبورها بخط العدّ، ثم يستخدم خط المنتصف لتحديد الاتجاه.
- **التحكم بالمعالجة:** يعمل التتبع في مسار منفصل عن خادم الويب، مع دعم الإيقاف المؤقت والاستئناف والإيقاف النهائي.
- **عرض التحليل والتقرير:** يرسل الخادم الإطارات والإحصائيات إلى واجهة ويب محلية، ويجمع التقرير الأعداد حسب الفئات المسعّرة.

## 6. نقاط الضعف والقيود المعروفة

- ملف الأوزان المطلوب غير مضمّن في Git؛ لن يعمل التطبيق على نسخة جديدة حتى يوضع `best(7).pt` يدويًا في `models/`.
- يعتمد العدّ على جودة الكشف والتتبع. قد يؤثر الحجب أو فقدان معرّف المركبة بين الإطارات في النتيجة.
- لا توجد أسعار محددة في التقرير للدراجات النارية أو أي فئات أخرى خارج السيارة والفان والشاحنة والباص؛ تدخل في إجمالي المركبات، ولا تدخل في الإيراد.
- يعتمد اتجاه الحركة على موضع المركبة بالنسبة إلى خط المنتصف، وليس على اتجاه عبور الخط الأفقي وحده.
- لا يتضمن المستودع حاليًا مجموعة اختبارات آلية موثقة.
